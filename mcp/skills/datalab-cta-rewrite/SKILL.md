## MCP 도구 연결

요청에 필요한 실제 도구가 현재 목록에 직접 보이면 그 도구를 사용한다. 보이지 않으면
사용자의 원래 의도를 `datalab_find_tools`에 보내고, 반환된 스키마와 도구 이름만 사용해
`datalab_call`로 실행한다. 도구 이름이나 인자를 지어내지 않는다. 결과가
`awaiting_confirm`이면 원래 호출을 반복하지 말고 ticket을 `datalab_confirm_status`로
확인한다.


# CTA 다시쓰기

블로그 글 마무리의 행동 유도 문구를 고쳐 쓴다. 산출물은 후보 문구 2~3개다 — 편집기에
자동으로 넣지 않는다. 붙여넣기는 사용자가 한다.

## 원문 확보

우선순위가 있다.

1. 사용자가 CTA 문구나 글 전체를 직접 붙여넣었으면 그것이 원문이다. 아래를 건너뛴다.
2. 지금 편집기에 열려 있는 초안이면 `editor_read` · `editor_read_structure` 로 읽는다.
3. 이미 발행한 글이면 `my_content_read` · `my_content_detail` 로 읽는다 — 어떤 글인지
   특정할 정보(제목·URL)가 있어야 한다.
4. 셋 다 없으면 원문이 없다. 글을 붙여넣거나 어떤 글인지 말해 달라고 하고 멈춘다.
   **지어내지 않는다.**

## CTA 찾기

원문에서 마무리 행동 유도 문단을 찾는다. 없으면(정보 전달만 하는 글) 새로 쓸 후보를
제시한다 — 기존 문장을 "고쳤다"고 하지 않는다.

## 검색어로 표현 다듬기 (해당하면)

CTA가 특정 상품·서비스를 가리키면 `search_keywords` · `autocomplete_keywords` 로 그 상품을
실제로 어떤 말로 검색하는지 확인하고 그 표현을 문구에 반영할 수 있다. 홍보 대상이 없는
정보 전달 글이면 이 단계는 생략한다.

검색어 통계는 **그 키워드를 검색한 사람들**의 것이지 이 블로그 독자의 것이 아니다.
"우리 독자는 20대 여성이 많다" 같은 문장의 근거로 쓰지 않는다.

## 다시쓰기

원칙은 `references/principles.md`. 형식은 `references/output-format.md`.

## 지어내지 않는다

- 전환율·클릭률 예측, 개선율, ROI, 매출 증가액 — 관측할 도구가 없다.
- "만 명이 선택한", "N% 만족" 같은 검증 안 된 숫자 — 실제로 집계한 값이 아니면 쓰지 않는다.
- 재고·마감 임박 같은 사실이 아닌 긴급성 — 사용자가 사실이라고 확인해 준 것만 쓴다.
- A/B 테스트 설계, 샘플 크기 계산 — 트래픽을 나눠 보여줄 도구가 없다.

## 이 스킬이 하지 않는 것

- 편집기를 직접 고치지 않는다. 후보를 내고 적용은 사용자가 한다.
- 상품 상세페이지·랜딩페이지는 다루지 않는다 — 네이버 블로그 편집기만 읽는다.
- 스토어 매출로 이 CTA가 얼마나 팔렸는지 잇지 않는다. 어떤 독자가 어떤 글을 보고
  구매했는지 이어 볼 도구가 없다 — 이으면 상관을 인과로 둔갑시키는 것이다.
