## MCP 도구 연결

요청에 필요한 실제 도구가 현재 목록에 직접 보이면 그 도구를 사용한다. 보이지 않으면
사용자의 원래 의도를 `datalab_find_tools`에 보내고, 반환된 스키마와 도구 이름만 사용해
`datalab_call`로 실행한다. 도구 이름이나 인자를 지어내지 않는다. 결과가
`awaiting_confirm`이면 원래 호출을 반복하지 말고 ticket을 `datalab_confirm_status`로
확인한다.


# 소재 제안

블로그에 다음에 뭘 쓸지 정하는 걸 돕는다. 산출물은 후보 소재 목록과 각 소재를 고른
근거다 — 원고를 쓰지는 않는다.

## 무엇부터 하나

1. 플랫폼과 카테고리가 이미 정해져 있으면(예: "네이버 블로그 육아 소재") 바로 조사로
   들어간다.
2. 안 정해져 있으면 `references/discovery.md` 의 질문 순서로 먼저 묻는다.
   플랫폼·카테고리는 필수, 타겟과 목적은 있으면 좋고 없어도 진행한다.
3. 조사가 끝나면 후보를 추리고 `references/output-format.md` 형식으로 낸다.

## 네이버 블로그 밖의 플랫폼

유튜브·인스타그램·브런치·티스토리 요청도 받는다. 다만 이 확장의 도구는 전부 네이버
데이터다 — 다른 플랫폼 소재는 `references/discovery.md` 의 일반 지식(포맷·시즌 패턴)으로만
제안하고, 검색량이나 경쟁 콘텐츠를 **확인했다고 말하지 않는다**. 네이버 블로그일 때만
도구로 뒷받침한다.

## 조사

네이버 블로그 소재라면 아래 순서로 확인하고, 확인한 것만 근거로 쓴다.

1. **니즈** — `search_keywords` · `autocomplete_keywords` 로 실제 검색어를,
   `kin_question_demand` 로 못 풀린 질문을 본다.
2. **시의성** — `daily_trend` · `my_soaring` 로 지금 오르는 것을, `keyword_trend` ·
   `keyword_yoy` 로 계절성을 본다.
3. **경쟁** — `search_blog` 로 상위 글을, `blog_profile` · `blog_posts` 로 경쟁 블로그를
   본다. 상위 글이 다루지 않은 부분이 차별화 지점이다.
4. **본인 강점** — 기존 방향을 물었다면 `my_top_content` 로 이미 잘 된 글을 확인해
   소재와 엮는다.

**호출은 라운드당 한 번씩만** — 후보 소재마다 매번 다시 조회하지 않는다. 조사는 한 번,
후보는 그 결과에서 여러 개 뽑는다.

## 앵글과 시리즈

같은 소재도 접근이 여러 개다: 방법형 / 목록형 / 비교형 / 경험담형 / 문제해결형 /
오해바로잡기형 / 타겟특화형 / 심화형. 후보마다 다른 앵글을 섞는다 — 전부 "가이드"면
다양성이 없는 것이다. 템플릿은 `references/discovery.md`.

시리즈로 묶을 수 있으면 표시한다: 심화형(입문→고급) / 확장형(영역별) / 기간형(N일차) /
사례형.

## 점수를 지어내지 않는다

"추천도 95%", "검색잠재력 20/25" 같은 가중치 점수를 쓰지 않는다 — 계산한 적 없는 수를
적으면 모델이 사실처럼 말하게 된다.

- 셀 수 있는 것(도구가 준 검색량, 실제 순위, 상위 글 개수)은 숫자 그대로 인용한다.
- 셀 수 없는 것(차별화 정도, 반응 예상, 경쟁력)은 점수를 매기지 않고 **왜 그렇게 보는지**
  한 줄로 쓴다 — "상위 10개 글 중 8개가 15개월 이전 글이다" 처럼 확인한 사실을 근거로 댄다.
- 소재 유형(트렌드형/에버그린형/니치형/리사이클형)은 범주 표시이지 점수가 아니라서 남긴다.
- 별점·난이도 등급도 뺐다 — 실제로 재본 적 없는 주관적 등급이다.

## 이 스킬이 하지 않는 것

- 원고를 쓰지 않는다. 소재가 정해지면 사용자가 초안 작성을 요청해야 한다.
- 소재를 자동으로 발행 캘린더에 넣지 않는다.
- 투자·의료·법률 카테고리 소재는 정보 전달 소재로만 제안한다. 확정적 조언이나 수익 보장
  표현은 쓰지 않는다.
