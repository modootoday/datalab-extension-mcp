# 출력 틀

사용자가 그대로 복사해서 붙여넣을 수 있어야 한다. 분석 리포트가 아니라 완성된 카피다.

## 단일 플랫폼

```
## [플랫폼명]

[캡션 본문]

글자수: N자 / 한도 M자
해시태그: #태그1 #태그2 #태그3
```

## 여러 플랫폼

플랫폼마다 위 블록을 만들고 `---` 로 구분한다. 맨 끝에 플랫폼별 차이를 한 줄씩 요약해도
된다 — 예: "X는 링크 클릭 유도, LinkedIn은 근거 제시 중심으로 톤을 바꿨다." 이건 **작성
방침 설명**이지 성과 예측이 아니다.

## 두 가지 버전을 요청받았을 때

버전 A / B 로 나란히 낸다. 차이는 "질문형 후크 vs 사실형 후크"처럼 **선택한 기법**으로
설명한다. 어느 쪽이 더 잘 될지는 말하지 않는다 — 판단은 사용자 몫이다.

## 넣지 않는 것

아래는 결과물에 넣지 않는다. 요청받아도 왜 안 되는지 설명한다.

| 뺀 것                                     | 왜                                                       |
| ----------------------------------------- | -------------------------------------------------------- |
| "예상 참여도 82/100", 참여 요인 가중치 표 | 측정한 적 없는 수. 매 요청마다 다른 숫자를 지어내게 된다 |
| "최적 게시 시간대"                        | 이 계정·이 독자를 관측한 데이터가 없다                   |
| A/B 버전 승자 판정, 개선율 %              | 실제로 게시하고 비교한 적이 없다                         |
| 구조화된 JSON 출력 스키마                 | 패널은 사람이 읽는 답변만 받는다                         |
| "품질 검증 완료" 배지, 원본 보존율 95% 류 | 아무 기준으로도 검증하지 않았다                          |
| 발행 타임라인                             | 이 스킬은 게시하지 않는다                                |

## 길이

캡션은 각 플랫폼 글자수 한도를 넘기지 않는다. 넘으면 핵심 메시지를 더 추리거나 여러
포스트로 나누라고 제안한다 — 억지로 욱여넣지 않는다.
