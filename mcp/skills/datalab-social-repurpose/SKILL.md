## MCP 도구 연결

요청에 필요한 실제 도구가 현재 목록에 직접 보이면 그 도구를 사용한다. 보이지 않으면
사용자의 원래 의도를 `datalab_find_tools`에 보내고, 반환된 스키마와 도구 이름만 사용해
`datalab_call`로 실행한다. 도구 이름이나 인자를 지어내지 않는다. 결과가
`awaiting_confirm`이면 원래 호출을 반복하지 말고 ticket을 `datalab_confirm_status`로
확인한다.


# 소셜 공유 초안

블로그 글 한 편을 X·Threads·Instagram·LinkedIn 각각의 분량과 문화에 맞는 카피로 다시
쓴다. 복사해서 바로 붙여넣을 수 있는 텍스트가 산출물이다.

## 무엇을 읽고 시작하나

우선순위가 있다.

1. 사용자가 글을 직접 붙여넣었거나 파일 경로를 줬으면 **그것이 원문이다.** 아래를
   건너뛴다.
2. 아니면 데이터랩툴즈 확장에서 읽는다 (아래).
3. 둘 다 없으면 원문이 없다. 글을 붙여넣거나 어떤 글인지 말해 달라고 하고 멈춘다.
   **지어내지 않는다.**

## 데이터랩툴즈 확장 연계

- `editor_read` · `editor_read_structure` — 지금 네이버 에디터에 열려 있는, 아직 발행
  전인 초안을 읽는다.
- `my_content_read` · `my_content_detail` — 이미 발행한 글의 본문을 읽는다. 어떤 글인지
  특정할 정보(제목·URL 등)가 있어야 찾는다.

이 스킬은 **읽기만 한다.** 위 넷 외에는 아무것도 부르지 않는다 — 글을 고치거나 제목을
바꾸는 일은 이 스킬의 몫이 아니다.

확장이 없거나 도구가 안 보이면 1번(붙여넣기)으로 동작한다 — 그것이 실패가 아니라 기본
경로다.

### 없는 것 (찾지 마라)

- SNS에 **직접 게시하거나 예약하는** 도구는 없다. 산출물은 초안이고 올리는 것은 사용자
  몫이다.
- **참여도·도달률을 계산하거나 예측하는** 도구는 없다.
- **이미지·영상을 만드는** 도구는 이 스킬의 범위가 아니다. 캡션 텍스트만 다룬다.

## 절차

**1. 원문에서 핵심을 추린다.** 문단 전체를 압축하지 말고, 이 글이 말하는 핵심 메시지
2~4개를 먼저 뽑는다. 나머지는 버려도 되는 디테일이다.

**2. 대상 플랫폼을 정한다.** 사용자가 지정했으면 그것만 쓴다. 지정이 없으면
X·Threads·Instagram·LinkedIn 네 곳 전부를 만든다. 다른 플랫폼은 요청받았을 때만,
그리고 요청받아도 텍스트 캡션만 낸다.

**3. 플랫폼별로 다시 쓴다.** 분량·어투·해시태그·이모지 관행은
`references/platform-specs.md`.

**4. 정해진 형식으로 낸다.** 틀은 `references/output-format.md`.

## 수치를 지어내지 않는다

- **셀 수 있다**: 결과물의 글자수, 해시태그 개수, 이모지 개수. → 세어서 쓴다.
- **셀 수 없다**: 예상 참여도, 예상 도달률, "이 버전이 더 잘 될 것" 같은 승패 판정,
  최적 게시 시간대. → **쓰지 않는다.**

두 가지 버전을 요청받으면 **스타일 차이만** 설명하고 점수는 매기지 않는다.

## 길이

플랫폼을 여러 개 한 번에 만들면 답변이 길어진다. 너무 길어질 것 같으면 플랫폼 수를
줄이거나("먼저 X·Threads만 드릴게요") 우선순위를 물어본다. 없는 참여도 표를 채워서
길이를 벌지 않는다.
