# 명세서 틀

명세서는 **다음 글을 쓸 사람(또는 모델)이 읽을 지시서**다. 분석 보고서가 아니다.
읽고 나서 무엇을 해야 할지 모르겠으면 그 줄은 빼야 한다.

## 틀

```markdown
# <이름> 문체 명세

## 한 줄

[이 사람 글을 못 읽어 본 사람이 읽고도 흉내 낼 수 있는 한 문장]

## 표본

- N편 / 제목 목록
- 출처: 붙여넣기 | 발행글 읽기
- [표본이 3편 미만이거나 한 주제에 몰려 있으면 여기 적는다]

## 규칙 — 이대로 쓴다

1. [따를 수 있는 형태로. "문장은 대체로 40자 안쪽, 두 줄을 넘기지 않는다"]
2. [...]
   각 규칙 밑에 **표본에서 가져온 문장 하나**를 붙인다.

## 하지 않는 것

- [표본에 한 번도 없는 것 중, 안 적으면 딸려 들어올 만한 것]
- [예: "이모지를 쓰지 않는다", "'~같아요' 로 끝내지 않는다"]

## 따라 하기 어려운 것

- [흉내 내려다 어색해지는 것. 억지로 넣지 말라고 함께 적는다]

## 확인

- [ ] 규칙마다 표본 인용이 붙어 있다
- [ ] 점수·퍼센트가 없다
- [ ] "하지 않는 것" 이 비어 있지 않다
```

## 넣지 않는 것

아래는 명세서에 넣지 않는다. 요청받아도 왜 안 되는지 설명한다.

| 뺀 것                                                       | 왜                                             |
| ----------------------------------------------------------- | ---------------------------------------------- |
| "AI 재현 가능성 95%+", "원본과 95% 이상 유사"               | 측정한 적 없는 수. 적으면 모델이 사실로 말한다 |
| 격식도 1-10, 친근감 X% : 전문성 Y%                          | 세는 방법이 없다. 인용이 같은 일을 더 잘한다   |
| TTR / MTLD 같은 지수                                        | 눈으로 못 구한다. 요구하면 지어낸 숫자가 온다  |
| "품질 보증 인증" 절 (완성도·전문가 검토·프로덕션 적용 가능) | 아무도 검토하지 않았다                         |
| 문서 메타데이터 (파일 크기·형식·작성 시기)                  | 문체와 무관하고, 추정하면 틀린다               |

## 길이

명세서가 표본보다 길면 뭔가 잘못됐다. 규칙 5~10개면 충분하고, 지킬 수 없는 규칙 20개보다
지킬 수 있는 규칙 5개가 낫다.
